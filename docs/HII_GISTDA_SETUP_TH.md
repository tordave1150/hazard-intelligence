# ขั้นตอนเตรียม HII และ GISTDA

ตรวจหน้าเว็บทางการวันที่ 26 ตุลาคม 2569 โครงการนี้ใช้ส่วนตัว เผยแพร่ฟรี และไม่เชิงพาณิชย์ ตามที่ผู้ใช้ยืนยัน ผู้ใช้มี GISTDA key และยืนยันว่าเปลี่ยน key/อัปเดต GitHub Secret หลังภาพล่าสุดแล้ว ยังไม่ได้เผยแพร่ข้อมูล GISTDA หรือ HII เข้า production

## ผลตรวจแล้วและขั้นตอนถัดไป

ผล [run 40364997446](https://github.com/tordave1150/hazard-intelligence/actions/runs/40364997446) บน `9659197` ยืนยันว่า client ใหม่เรียก **Features API** ได้สำเร็จ: **HTTP 200**, `window=1day`, `ap_idn=2604` (องครักษ์), **numberMatched=0 / numberReturned=0** เวลาตอบ API คือ **27 ต.ค. 2569 เวลา 00:03:33.525 ICT** ไม่ใช่เวลาถ่ายภาพ ทุก step ผ่านและไม่ได้เขียนข้อมูลลง Atlas

Endpoint คือ `https://api-gateway.gistda.or.th/api/2.0/resources/features/flood/1day` ใช้ **header `API-Key`** และ query รหัสพื้นที่ ต่างจาก point route เก่าที่ใช้ lat/lon/area และตอบ 404 ดู [ผลตรวจปัจจุบัน](gistda-disaster-features-review-2026-10-26.md) สำหรับหลักฐานแยกแต่ละ route

ตรวจช่วง **30days แบบไม่กรองอำเภอสำเร็จแล้ว** ใน run 40371542079/40372062673 ได้ HTTP 200 และอ่านมาเพียง **1 รายการจากที่ API รายงาน 184,323 รายการ** ตรวจชื่อ/ชนิดของ properties ครบ 29 ฟิลด์ แต่ยังไม่ยืนยันหน่วยพื้นที่หรือฟิลด์เวลาถ่ายภาพ จึงไม่ใช้ข้อมูลนี้แทน 1day และไม่เผยแพร่ geometry

ขั้นถัดไปบันทึกคำขอ `2026-10-27-03` ใน `.github/gistda-inspection.json`: **service=stac, window=1day, ap_idn ว่าง** เพื่ออ่าน metadata ของ STAC item ที่ catalog ทางการเชื่อมไว้ โดยไม่ดาวน์โหลดภาพ อ่าน key จาก secret เดิม และเริ่มเองเมื่อ push คำขอบน main ไม่ต้องให้ผู้ใช้กด Run ซ้ำ

ไฟล์คำขอต้องมี request_id, window, ap_idn และเลือก service=features/stac เพิ่มได้ ไม่รับ key หรือ URL เปลี่ยนได้เฉพาะผลิตภัณฑ์ที่เอกสารระบุ การ push ไฟล์อื่นหรือ pull request ไม่เริ่ม diagnostic นี้ ค่า datetime ของ STAC อาจเป็นเวลาตัวแทนของภาพรวม จึงยังไม่ถือเป็นเวลาถ่ายภาพของทุกพื้นที่

หากผู้ใช้ต้องการเริ่มเอง ยังใช้ [Inspect GISTDA Disaster Features](https://github.com/tordave1150/hazard-intelligence/actions/workflows/gistda-access.yml) → Run workflow รอบใหม่ → main → เลือก window/ap_idn อย่างชัดเจนได้ ไม่ใช้ Re-run jobs ของรอบเก่าเพราะจะใช้ commit/พารามิเตอร์เดิม

นี่เป็น workflow ตรวจตามคำขอ ไม่มี schedule ไม่เขียน Atlas และไม่เปิด layer เอง อ่าน key จาก Actions เท่านั้น แล้วส่งผ่าน header โดยไม่พิมพ์ค่าลับ โปรแกรมทิ้ง `links` จาก response ก่อนรายงาน เพราะ upstream อาจแนบ key กลับมาใน href แม้ request จะใช้ header ห้ามคัดลอก response ทั้งก้อนหรือภาพที่มี key มาเผยแพร่

HTTP 200 พร้อม FeatureCollection ที่มี numberMatched=0 / numberReturned=0 หมายถึงคำขอนั้นตอบสำเร็จแต่ไม่มีรายการ ไม่ยืนยันว่าไม่มีน้ำท่วมหรือดาวเทียมครอบคลุมครบ `timeStamp` เป็นเวลาตอบ API ไม่ใช่เวลาถ่ายภาพ หากพบรายการ โปรแกรมรายงานเฉพาะโครงสร้าง field/type และจำนวน ไม่พิมพ์ค่าของ feature และยังไม่ถือว่าผ่าน source acceptance

window 3days / 7days / 30days เป็นผลิตภัณฑ์คนละช่วงเวลาที่เอกสารระบุ ต้องเลือกเองและติดป้ายตามจริง ไม่มีการสลับอัตโนมัติหรือเอาข้อมูลหลายวันมาเรียกว่าหนึ่งวัน

[Resource หนึ่งวันของ Disaster Platform](https://opendata.gistda.or.th/th/dataset/flood-disaster-data/resource/062a08da-a6a9-4db7-9af7-1d345e38563a) ระบุ **License not specified** จึงยังต้องยืนยันสิทธิ์เผยแพร่/attribution และ sample ที่มี acquisition time, geometry, CRS, quality/coverage ก่อนทำ layer สาธารณะ ไม่ใช้ Open Data Common ของ catalog point route เก่าแทนผลิตภัณฑ์นี้

เตรียม [ร่างคำถามสำหรับผู้ดูแลผลิตภัณฑ์ปัจจุบัน](GISTDA_DISASTER_PRODUCT_QUESTIONS_TH.md) ไว้แล้ว ครอบคลุมเงื่อนไขเผยแพร่ เวลา/คุณภาพ ผลลัพธ์ว่าง/coverage และ quota ยังไม่ได้ส่งให้หน่วยงาน

หากเผลอเผย key อีก ให้เพิกถอนและสร้างใหม่ใน GISTDA จากนั้น GitHub Actions secrets → `GISTDA_API_KEY` → Edit → แทนค่าด้วย key ใหม่ → Update secret แจ้งเพียงว่าเปลี่ยนแล้ว การเปลี่ยน credential ต้องทำในบัญชีผู้ใช้เอง

## 1. อ้างอิงการสมัคร GISTDA สำหรับบัญชีใหม่

1. เปิด [GISTDA API Gateway](https://api-gateway.gistda.or.th/) ระบบที่ตรวจเปลี่ยนไปหน้า `/v2/a/signin`
2. เลือก **เข้าสู่ระบบด้วย อีเมล** แล้วเลือก **ลงทะเบียน** จะถึง [หน้าลงทะเบียน](https://api-gateway.gistda.or.th/v2/a/signup)
3. กรอก **ชื่อ นามสกุล อีเมล รหัสผ่าน** ด้วยตัวเอง อ่านรายละเอียดของ checkbox/เงื่อนไขการให้บริการและนโยบายก่อนเลือก แล้วกดลงทะเบียนด้วยตัวเอง ไม่ต้องส่งรหัสผ่านหรือรหัสยืนยันในแชต
4. ทำขั้นตอนยืนยันบัญชีตามที่ระบบแสดง จากนั้นเข้าสู่ระบบ แล้วเปิดบริการ **Disaster Platform / ข้อมูลน้ำท่วม** ที่บัญชีของคุณขอใช้ได้ อ้างอิง [บริการทางการ](https://disaster.gistda.or.th/landing/services) และ [บัญชีชุดข้อมูลน้ำท่วม](https://opendata.gistda.or.th/th/dataset/flood-disaster-data)
5. ส่งกลับมาเฉพาะ **ลิงก์หน้าเอกสาร API หรือชื่อผลิตภัณฑ์/สิทธิ์ที่ได้รับ** และลิงก์เงื่อนไขการเผยแพร่ ไม่ต้องคัดลอก key, token หรือ URL ที่มี key แนบอยู่

หน้าเงื่อนไขผลิตภัณฑ์หลังเข้าสู่ระบบยังไม่ได้ตรวจ บัญชีชุดข้อมูลสาธารณะที่ตรวจระบุ `License not specified` จึงต้องยืนยันสิทธิ์เผยแพร่แผนที่/ข้อมูลบนเว็บสาธารณะก่อนเปิด layer การมีบัญชีเพียงอย่างเดียวยังไม่ยืนยันสิทธิ์ผลิตภัณฑ์หรือการเผยแพร่ต่อ

ขณะนี้มี workflow ตรวจ Disaster Platform Features แบบ manual ตามขั้นตอนด้านบนแล้ว แต่ยังไม่มี workflow เผยแพร่ข้อมูล GISTDA งาน ETL จริงจะเริ่มหลังยืนยันเอกสาร/สิทธิ์/พารามิเตอร์และข้อมูล sample ผ่าน source acceptance การเก็บ key อยู่เฉพาะ backend/Actions ไม่อยู่ใน browser หรือ public repository

ผมเปิดอ่านถึงหน้าลงทะเบียนเปล่าแล้ว ยังไม่ได้ส่งข้อมูล สมัครบัญชี เลือก checkbox หรือยอมรับเงื่อนไขแทนคุณ

## 2. HII / ThaiWater: ขอสิทธิ์สำหรับข้อมูลล่าสุด

[HII Open Data](https://data.hii.or.th/) มี [ระดับน้ำ](https://data.hii.or.th/dataset/water-level) และ [ฝน](https://data.hii.or.th/dataset/hii-rainfall) แบบไฟล์ CSV รายเดือนเปิดให้ดาวน์โหลดโดยไม่ต้องใช้ key รายการที่ตรวจระบุ Creative Commons Attribution Non-Commercial แต่ไฟล์ย้อนหลังรายเดือนไม่ใช่ API สถานการณ์ปัจจุบัน

ผลตรวจจริง: metadata รวมมี 1,396 ระเบียน; โฟลเดอร์ระดับน้ำเดือนตุลาคม 2569 ยังไม่มี CSV ณ เวลาตรวจ โฟลเดอร์กันยายนมี metadata และข้อมูลสถานี ตัวอย่าง ATG011 มี 4,320 ช่วงเวลา ถึง **30 ก.ย. 2569 เวลา 23:50 ตามข้อความในไฟล์** ยังไม่ได้ยืนยัน timezone หรือความหมาย quality flag จึงไม่แสดงเป็นระดับน้ำปัจจุบัน และไม่เปลี่ยนเวลานั้นเป็น UTC เอง

สำหรับข้อมูลล่าสุด ให้ติดต่อช่องทางในบัญชีข้อมูล HII: **telem@hii.or.th** หรือช่องทางขอข้อมูลที่หน้า HII ระบุ โดยขอข้อมูลต่อไปนี้พร้อมกัน:

- endpoint/API ทางการสำหรับระดับน้ำและ/หรือฝนล่าสุด พร้อมวิธีออก token ให้โครงการ
- รายชื่อสถานีและพิกัด, หน่วย, datum ของระดับน้ำ, timezone และความหมาย quality flags/ค่าข้อมูลหาย
- ความถี่อัปเดต เวลาหน่วง ขอบเขตพื้นที่ และ quota
- สิทธิ์แสดงข้อมูลและพิกัดบนเว็บส่วนตัวที่เปิดให้ประชาชนใช้ฟรี พร้อมข้อกำหนด attribution
- เกณฑ์ตลิ่ง/เตือนภัยและที่มาของเกณฑ์ ถ้าผลิตภัณฑ์มีเผยแพร่; ไม่สร้างเกณฑ์เอง

ข้อความสำหรับนำไปปรับและส่งเอง:

> ต้องการใช้ข้อมูลสถานีฝน/ระดับน้ำล่าสุดในโครงการ Thailand Hazard Intelligence เว็บไซต์ส่วนตัวที่เผยแพร่ฟรี ไม่เชิงพาณิชย์ เพื่อแสดงค่าที่สถานีวัดได้พร้อมหน่วย datum เวลา และแหล่งที่มา โดยประมวลผลผ่านงาน ETL แยกจากเว็บไซต์และเก็บเฉพาะ snapshot ล่าสุด ขอทราบ API/สิทธิ์เข้าถึง quota เอกสาร metadata/quality flags และเงื่อนไขการเผยแพร่ข้อมูลและพิกัดบนเว็บสาธารณะ รวมถึงการระบุแหล่งที่มาที่ถูกต้อง

ยังไม่ได้ส่งข้อความนี้หรือติดต่อหน่วยงานแทนคุณ [ThaiWater.Standard](https://standard.thaiwater.net/docs/) เป็นข้อกำหนดแลกเปลี่ยนข้อมูล; ตัวอย่าง endpoint/token ในเอกสารไม่ใช่สิทธิ์ใช้ live nationwide API ของโครงการนี้

## 3. ขอบเขตลุ่มน้ำ

บัญชี [พื้นที่ 22 ลุ่มน้ำตามพระราชกฤษฎีกา](https://gdcatalog.go.th/dataset/gdpublish-dataset-32-0113) ของ ONWR มีไฟล์ SHP ทางการ แต่ metadata ที่ตรวจยังระบุ `License not specified` ต้องได้เงื่อนไขอนุญาตเผยแพร่ geometry หรือพบ resource ทางการที่มีสิทธิ์ชัดเจนก่อนใช้ ส่วนแผนผังน้ำ/ชั้นคุณภาพลุ่มน้ำเป็นคนละผลิตภัณฑ์ ไม่ใช้สิทธิ์ของผลิตภัณฑ์หนึ่งแทนอีกผลิตภัณฑ์

เมื่อได้รับสิทธิ์/เอกสารแล้วจึงทำ adapter และทดสอบ sample จริง ก่อนเปิด layer ปัจจุบัน Weather, RID และ TMD ทำงานแยกต่อไปได้
